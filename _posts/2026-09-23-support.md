```csharp

public class Protected
{
    private static byte[] key = Encoding.ASCII.GetBytes("armando");
```

## Privilege Escalation

### Identifying the privilege-escalation path

After obtaining the user flag, I revisited BloodHound and inspected the `support` account.

![BloodHound](/assets/img/posts/support/bloodhound.png)

The `support` account has **GenericAll** over the `DC` computer object. This permission allows us to modify the computer object and configure an RBCD (**resource-based constrained delegation**) attack.

### About RBCD

>Resource-Based Constrained Delegation is a Kerberos delegation mechanism. It enables a service (the front-end service) to impersonate a user and access a resource (the back-end service) on that user’s behalf. What makes RBCD unique is that the configuration is stored on the resource object in Active Directory (AD), rather than on the front-end service account. This allows the resource owner, who often lacks broad administrative privileges, to manage delegation permissions for their specific resource.


### Creating a controlled computer account

I first added a computer account to the domain. By default, users can create up to ten computer objects through the MachineAccountQuota setting.

```bash
└──╼ #bloodyAD --host 10.129.230.181 -d support.htb -u support -p 'Ironside47pleasure40Watchful' add computer tr3m0x  Password123
[+] tr3m0x$ created
```
